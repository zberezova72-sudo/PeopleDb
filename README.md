## Запуск

Потрібен [.NET SDK 8.0](https://dotnet.microsoft.com/download) або новіший.

```bash
git clone <URL-вашого-репозиторію>
cd PeopleDb
dotnet run --project src/PeopleDb.App
```

Файл бази за умовчанням — `people.txt` у поточній теці. Інший шлях передається аргументом:
`dotnet run --project src/PeopleDb.App -- data/my.txt`.

**Швидка демонстрація:** у меню оберіть `1` (демо-дані: 12 осіб), потім `8` (результат варіанту — **3**), `3`, `4`, `5`, `7`, `6`.

## Структура рішення

| Проект | Призначення |
|---|---|
| `src/FileStorage` | **Лише** читання/запис файлу через потоки (`FileStream`, `StreamReader`, `StreamWriter`). Жодної предметної області та консолі. |
| `src/PeopleDb.Core` | Сутності, вміння (інтерфейси), специфікації, дескриптори (відображення на файл), репозиторій, регулярні вирази. Без консолі. |
| `src/PeopleDb.App` | `ConsoleMenu` (весь ввід/вивід), корінь композиції `Program.cs`, демо-дані. |

Діаграма класів: [docs/ClassDiagram.md](docs/ClassDiagram.md).

## Формат файлу (один файл для всіх типів)

```
Student ОксанаКоваленко
{ "firstname": "Оксана",
"lastname": "Коваленко",
"studentId": "КВ123456",
"course": "1",
"gender": "Ж",
"residence": "5.312",
"lessons": "0",
"skatingSessions": "0"};
Pilot ВікторГончар
{ "firstname": "Віктор", ... };
```

Запис і читання йдуть **поелементно** (заголовок, потім атрибут за атрибутом); при читанні також приймаються типографські лапки “ ”.
Невідомий тип у файлі дає зрозуміле повідомлення про помилку.

## Сутності та валідація (регулярні вирази — `Core/Validation/Rules.cs`)

| Тип | Обов'язкові атрибути | Формат |
|---|---|---|
| Student | прізвище, ім'я, студентський квиток, курс, стать, місце проживання | квиток `КВ123456` (2 літери + 6 цифр); курс 1–6; стать Ч/Ж; гуртожиток `номер.кімната` (напр. `5.312`) або адреса |
| Musician | прізвище, ім'я, `musicianId`, `instrument` | `MU100001` |
| Pilot | прізвище, ім'я, `licenseNumber` | `PL-200001` |

Необов'язкові (за умовчанням 0): `lessons`, `piecesPlayed`, `flightHours`, `skatingSessions`.
Ім'я/прізвище — літери, апостроф, дефіс. Унікальний ідентифікатор — `Person.Id`.

## Відповідність вимогам

- **Задовільно:** файловий ввід-вивід та консоль — в окремих класах, не в сутностях.
- **Добре:** окремий проект `FileStorage` (мінімум 2 проекти); весь екранний ввід-вивід у `ConsoleMenu`; абстракції (`IPerson`/`Person`, `IResidence`, `IRecordStore`, `IPersonRepository`, інтерфейси вмінь).
- **Відмінно:** новий тип (напр. `Pupil`) = сутність + дескриптор + один рядок у `Program.cs`; нове вміння = інтерфейс + одна `PersonAction` у `Program.cs`. Існуючий код не змінюється (Open/Closed). `Play()` може виконувати будь-яка сутність, що реалізує `IPlayer`.
- **Підвищена складність:** усі типи зберігаються в одному файлі.
- **Принципи:** композиція замість наслідування (`SkatingSkill` вбудовується в сутності; `Student` має `IResidence`), слабка зв'язність (залежність від інтерфейсів), інверсія керування (усі залежності передаються через конструктори в `Program.cs`).
- **Без колекцій:** лише масиви (неявні `using` вимкнено, `System.Collections.*` не використовується).
- **Методи предметної області змінюють стан** (`Study`, `Play`, `Fly`, `Skate` збільшують лічильники), друк робить лише `ConsoleMenu`.
- Видалення/оновлення: запис у тимчасовий файл і підміна через `Commit` — збій не псує базу.
